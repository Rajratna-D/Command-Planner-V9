# Changelog Maintenance Policy

Whenever you make any changes to this codebase—whether minor or major:
1. **Always update `CHANGELOG.md`** located at the repository root (`CHANGELOG.md`).
2. Follow the standard entry format specified in `CHANGELOG.md`.
3. Every entry must explicitly state:
   - **Type / Scope**: (Major | Minor | Patch | Security | Performance | Refactor | Docs)
   - **Affected Files**: Precise list of modified, added, or deleted files and functions.
   - **What Changed**: Technical summary of the modification.
   - **Reason Behind the Change**: The problem, vulnerability, bug, or user requirement that prompted the work.
   - **Outcome / Goal**: The concrete result, verification evidence, test pass status, or benchmark achieved.
